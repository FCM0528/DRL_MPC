# 策略与训练版本

Git 仓库只收录当前注册的通用/区域策略、60/80 km/h 固定策略及其必要快照；其余训练状态、审计报告和历史仿真产物保留在本机，不随源码仓库上传。文中指向未收录目录的路径是本地研究记录。

本目录集中保存策略文件及其来源，原 `results` 目录中的历史记录仍保留。

若某训练目录含 `invalid_training.txt`，表示该训练因已确认的执行问题无效，只作审计；默认续训和三控制器对比不会把它当作合格策略。本次 2026-10-29 的 17:11 两组实验因 CarSim 的站距终止条件先于 C++ 质心完成条件触发而被标记无效，不应用于判断收敛。

新结果子目录以实际算法和模式命名，例如 `td3_train_carsim_NpNominal15_Nc7_时间`。旧目录保持原路径，不影响已登记策略及训练状态的引用。

- `archive/`：历史 DDPG、TD3 的固定附着和变附着 Actor，附原训练配置、检查点、CarSim 源工况和来源路径。
- `iterations/ddpg/`、`iterations/td3/`：每次继续训练的独立版本。每个版本包含 `ddpg_policy.txt` 或 `td3_policy.txt`、`selected_validation.csv`、`rl_report.html`、源工况和轮胎数据。
- `candidates/`：从完整训练状态导出的候选 Actor；这些文件未经训练期选优，不会自动投入三组对照。
- `evaluations/`：跨速度与附着的独立验证结果。`generalization_report.html` 展示逐工况误差和理想侧向需求，CSV 保留明细。
- `catalog.csv`：各版本模型格式、训练 μ 范围、选中回合和 SHA-256；运行 `tools/update_policy_catalog.ps1` 可刷新。
- `active_registry.csv`：三组对照当前使用的两份通用策略及其验证来源。历史变附着策略先作为基线，并不表示全部工况绝对误差已达标。
- `region_registry.csv`：仅登记通过区域独立评估的历史专家。当前仅在 μ=0.4、目标车速 30–70 km/h 时自动使用 DDPG 专家；TD3 使用通用策略。每次运行开始时按工况选择，并在报告中标注。通用策略更新后若哈希变化，区域路由会暂停，直到重新评估，避免沿用过期结论。

在 μ=0.4 的 10 个未用于这些策略选优的速度点，DDPG 专家平均 RMSE 为 0.2189 m，历史变附着 DDPG 为 0.2692 m，专家在 9/10 点更低；TD3 专家和历史变附着 TD3 分别为 0.2558 m 和 0.2517 m，未显示整体优势，因此未启用 TD3 专家路由。这些结果只支持该车辆、轨迹和测试区域内的相对比较。

候选对照见 `tgt/p1/`（原奖励）、`tgt/p2/`（高峰值惩罚）、`tgt/p3/`（切换位置扰动后）与 `tgt/p4/`（扰动 DDPG 加高峰值 TD3）；`tgt/b1/`、`tgt/b2/` 是历史策略基准，每个目录均有场景汇总和逐场景图表。p3/p4/b2 额外包含两条未参与训练和训练期选优的道路。结果仅为单个训练种子；多次使用这些评估作调参会消耗其独立性。原道路目标工况属于选优工况，不能作为无偏泛化证据。36 工况检查保存在 `tgt/e0t/`、`tgt/e1d/`、`tgt/e1t/`、`tgt/e2t/`、`tgt/e3d/` 和 `tgt/e3t/`，其中部分低 μ 表后段低于策略输入下限，属于外推测试。

以前的策略文件只记录 Actor 参数，因此首次使用 `rl.warm_start_file` 只能继承 Actor，Critic、优化器和经验池重新初始化。固定 μ Actor 扩展到变 μ 范围时，程序会清除未训练的 μ 观测权重；变 μ 模型缩小范围时，会重算输入归一化。不同算法、动作范围或控制器模型的文件不能互相替代。

切换常附着和 STEP 变附着道路后，默认训练脚本会检查续训来源：如果道路导致完整状态不兼容，会从最近状态提取 Actor 并重新初始化 Critic 和经验池，记录在 `warm_start_manifest.txt`；后续相同道路可恢复完整状态。手动指定 `-ResumeState` 时仍严格要求兼容。变附着训练和评估按比例缩放原道路表，μ 标签为初始值；训练初始 μ 范围自动收缩以保证全表不超出输入范围，独立评估仍可能包含范围外的外推工况。同一道路下建立新的基线验证之前，不会把新道路的结果与旧道路基线直接比较并自动晋升。

新版本额外保存 `best_training_state.txt` 和 `last_training_state.txt`。前者对应选中的检查点，后者保留最后一次更新和经验池，可能尚未通过误差约束。续训时同时需要同目录的 `training_source_Run_all.par`、`training_state_context.txt` 和 `tire_data.csv`。程序会检查网络、奖励、动作范围、MPC 参数、轮胎及源工况；源工况可变更目标速度、路面 μ 和停止时间。其他车辆或道路变化应从 Actor 热启动，避免直接混用不兼容经验。

后续训练还会保存每 10 回合的 `checkpoint_XXXX_policy.txt` 和 `last_unvalidated_policy.txt`，它们是未必通过选优的原始 Actor，只用于诊断或继续研究，不能直接当作已验证部署策略。已有完整状态可用 `--rl-mode export_state --set rl.resume_state_file=<状态文件>` 导出未选优的 Actor；请使用相同的算法、奖励和动作配置，并执行独立评估。

在 CarSim Browser 打开并更新工况后，可在项目根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\train_general_policy.ps1 -Algorithm ddpg
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\train_general_policy.ps1 -Algorithm td3
```

脚本默认训练 300 回合，范围 30–120 km/h、μ=0.3–0.9。首次从相应历史 Actor 初始化；之后默认从最近完成版本的末次训练状态继续，并改变采样随机种子。也可以用 `-ResumeState <完整状态文件>` 选择最佳检查点，或用 `-WarmStart <策略文件>` 指定 Actor。完成后默认执行 36 个独立速度/附着组合，并输出报告路径。通过相对验证门槛才更新 `active_registry.csv` 指针，旧策略和旧注册表备份均保留；加 `-NoPromotion` 只训练与评估，不更新指针。

自动更新需要同一车辆、道路和固定 MPC 基线、完整的 36 工况，且候选必须是学习或合格继承检查点。每个工况相对当前策略和固定 MPC 的 RMSE 不得超过 `1.10×参考+0.02 m`，最大误差不得超过 `1.10×参考+0.05 m`；完成状态不能退步。各 μ 分组平均 RMSE 不得超过当前策略的 `1.05×参考+0.005 m`，全工况平均 RMSE 至少改善 0.001 m。该门槛只约束相对退化，不代表高侧向需求工况已达到某个绝对跟踪精度。

参考轨迹的侧向需求可按 `v²|κ|/(μg)` 粗略衡量，超出理想摩擦上限时，仅靠固定车速的横向转向控制不能保证准确跟踪。完成整段仿真、训练奖励上升或生成策略文件，都不等于每个工况误差达标。
